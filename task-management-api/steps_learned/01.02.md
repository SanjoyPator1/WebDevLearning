# Task 1.2: Pydantic Models and Validation Implementation

## Step 1: Create Task Model with Validation

Create/Update `app/schemas/task.py`:

```python
from pydantic import BaseModel, Field, field_validator, model_validator
from typing import Optional, Literal, List
from datetime import datetime

class Task(BaseModel):
    """Main Task model with validation"""
    title: str = Field(..., min_length=1, max_length=100, description="Task title")
    description: Optional[str] = Field(None, max_length=500, description="Task description")
    priority: Literal["low", "medium", "high"] = "medium"
    due_date: Optional[datetime] = None
    completed: bool = False
```

**Explanation:**

- `Field(...)` means the field is required (the `...` is Pydantic's way of saying "required")
- `min_length=1, max_length=100` validates string length automatically
- `Optional[str]` means the field can be a string or `None`
- `Literal["low", "medium", "high"]` restricts values to only these three options
- Default values are provided for `priority` and `completed`

## Step 2: Implement Field Validation with Custom Validators

Add custom validators to the Task class:

```python
    @field_validator('title')
    @classmethod
    def validate_title(cls, v: str) -> str:
        """Custom validation for title field"""
        if not v or v.isspace():
            raise ValueError('Title cannot be empty or just whitespace')

        # Remove extra whitespace
        v = v.strip()

        # Check for forbidden characters
        if any(char in v for char in ['<', '>', '&', '"']):
            raise ValueError('Title contains forbidden characters')

        return v

    @field_validator('description')
    @classmethod
    def validate_description(cls, v: Optional[str]) -> Optional[str]:
        """Custom validation for description"""
        if v:
            v = v.strip()
            if len(v) == 0:
                return None  # Empty string becomes None
        return v

    @field_validator('due_date')
    @classmethod
    def validate_due_date(cls, v: Optional[datetime]) -> Optional[datetime]:
        """Ensure due date is not in the past"""
        if v and v < datetime.now():
            raise ValueError('Due date cannot be in the past')
        return v

    @model_validator(mode='after')
    def validate_completed_task(self):
        """Model validator to check business logic across fields"""
        # Example of cross-field validation
        if self.completed and self.due_date and self.due_date < datetime.now():
            # This is just an example - task was completed late, but that's okay
            pass

        return self
```

**Explanation:**

- `@field_validator('title')` validates individual fields
- `@classmethod` is required for field validators in Pydantic V2
- `@model_validator(mode='after')` validates the entire model after all fields are processed
- Field validators run before model validators
- You can transform data (like `.strip()`) or raise `ValueError` for invalid data

## Step 4: Add Response Models for Different Scenarios

Add these additional models after the Task class:

```python
class TaskResponse(BaseModel):
    """Response model for returning task data with ID and timestamps"""
    id: int
    title: str
    description: Optional[str]
    priority: Literal["low", "medium", "high"]
    due_date: Optional[datetime]
    completed: bool
    created_at: datetime
    updated_at: datetime

    class Config:
        # This allows creating from SQLAlchemy models later
        from_attributes = True
        json_schema_extra = {
            "example": {
                "id": 1,
                "title": "Complete FastAPI tutorial",
                "description": "Learn Pydantic models and validation",
                "priority": "high",
                "due_date": "2024-12-31T23:59:59",
                "completed": False,
                "created_at": "2024-01-01T10:00:00",
                "updated_at": "2024-01-01T10:00:00"
            }
        }


class TaskUpdate(BaseModel):
    """Model for updating tasks - all fields are optional"""
    title: Optional[str] = Field(None, min_length=1, max_length=100)
    description: Optional[str] = Field(None, max_length=500)
    priority: Optional[Literal["low", "medium", "high"]] = None
    due_date: Optional[datetime] = None
    completed: Optional[bool] = None

    # Reuse validators for fields that are provided
    @field_validator('title')
    @classmethod
    def validate_title(cls, v: Optional[str]) -> Optional[str]:
        if v is not None:
            if not v or v.isspace():
                raise ValueError('Title cannot be empty or just whitespace')
            v = v.strip()
            if any(char in v for char in ['<', '>', '&', '"']):
                raise ValueError('Title contains forbidden characters')
        return v

    @field_validator('description')
    @classmethod
    def validate_description(cls, v: Optional[str]) -> Optional[str]:
        if v is not None:
            v = v.strip()
            if len(v) == 0:
                return None
        return v


class TaskList(BaseModel):
    """Response model for list of tasks"""
    tasks: List[TaskResponse]
    total: int

    class Config:
        json_schema_extra = {
            "example": {
                "tasks": [],
                "total": 5
            }
        }
```

**Explanation:**

- `TaskResponse` includes ID and timestamps that don't exist when creating tasks
- `TaskUpdate` makes all fields optional for partial updates
- `TaskList` wraps multiple tasks with metadata
- `from_attributes = True` will be important when we connect to a database later

# Router Updates for Pydantic Models

## Why Use \*\* with Pydantic Models?

- TaskResponse(\*\*task) creates a new TaskResponse model by unpacking the dictionary as keyword arguments.
- This is a Python feature: `**dict` passes each key-value pair in the dictionary as a named argument.
- Pydantic uses these to validate and create a model instance.

**Example**

```python
task = {
    "id": 1,
    "title": "Learn FastAPI and Pydantic",
    "description": "Read docs",
    "priority": "medium",
    "due_date": None,
    "completed": True,
    "created_at": ...,
    "updated_at": ...
}
response = TaskResponse(**task)
```

- This ensures the response matches your schema and is validated.

### What is ** in Python?
- The `**` operator is called "dictionary unpacking".
- It takes a dictionary and passes each key-value pair as a named argument to a function or class.
**Example:**
```python
def greet(name, age):
    print(f"Hello {name}, you are {age} years old.")

info = {"name": "Alice", "age": 30}
greet(**info)  # Same as greet(name="Alice", age=30)
```

### How does this work with Pydantic models?
Suppose you have a Pydantic model:
```python
from pydantic import BaseModel

class TaskResponse(BaseModel):
    id: int
    title: str
    completed: bool
```

And you have a dictionary:

```python
task = {
    "id": 1,
    "title": "Learn FastAPI",
    "completed": True
}
```

You can create a validated Pydantic object like this:
```python
response = TaskResponse(**task)
# This is the same as TaskResponse(id=1, title="Learn FastAPI", completed=True)
```

### Why is this useful in FastAPI?
- When you fetch a task from your database (or in-memory list), it’s usually a dictionary.
- You want to return a validated response that matches your API schema.
- By using `TaskResponse(**task)`, you:
    - Validate the data (types, required fields, etc.)
    - Get automatic conversion to JSON for the API response

## Step 5: Update PUT Update Task Endpoint

```python
@router.put("/{task_id}", response_model=TaskResponse)
async def update_task(task_id: int, task_data: TaskUpdate):
    """Update a specific task by ID"""
    # Find task by ID
    task = None
    task_index = None

    for i, t in enumerate(tasks_db):
        if t["id"] == task_id:
            task = t
            task_index = i
            break

    if not task:
        raise HTTPException(status_code=404, detail="Task not found")

    # Update only provided fields
    update_data = task_data.model_dump(exclude_unset=True)
    for field, value in update_data.items():
        task[field] = value

    # Update timestamp
    task["updated_at"] = datetime.now()
    tasks_db[task_index] = task

    return TaskResponse(**task)
```

**Explanation:**

- `task_data: TaskUpdate` validates partial updates
- `model_dump(exclude_unset=True)` only gets fields that were actually provided in the request
- Only update provided fields, leave others unchanged
- Update the timestamp
- task_data is a Pydantic model (TaskUpdate) containing the fields the user wants to update.
- model_dump(exclude_unset=True) converts the model to a dictionary only including fields that were actually provided in the request (fields that are not None or not set).
- This prevents overwriting existing fields with None if the user didn’t send them.

**Example**
Suppose the original task is:

```
task = {
    "id": 1,
    "title": "Learn FastAPI",
    "description": "Read docs",
    "priority": "medium",
    "due_date": None,
    "completed": False,
    "created_at": ...,
    "updated_at": ...
}
```

The user sends an update request:

```
{
    "title": "Learn FastAPI and Pydantic",
    "completed": true
}
```

- ask_data will have only title and completed set.
- task_data.model_dump(exclude_unset=True) returns:

```
{
    "title": "Learn FastAPI and Pydantic",
    "completed": True
}
```

- The loop updates only those fields in the original task.
