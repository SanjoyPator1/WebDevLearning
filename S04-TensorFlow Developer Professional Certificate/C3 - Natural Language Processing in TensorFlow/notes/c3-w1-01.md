# 2. Word-Based Encodings

## Why Character Encoding Doesn't Work

### The ASCII Approach Problem

Character encodings like ASCII (American Standard Code for Information Interchange) assign numeric values to individual characters, but this approach has a fundamental flaw: **it doesn't capture word semantics**.

**Example: "Listen" vs "Silent"**

- Both words contain the exact same letters
- Both would have the same character encodings
- However, they have very different (almost opposite) meanings
- The semantic meaning of a word is not encoded in its individual letters

**Conclusion**: Training a neural network using only character-level encodings would be extremely challenging and ineffective for understanding meaning.

## Word-Based Encoding Concept

Instead of encoding individual characters, we can assign values to entire words. This approach begins to capture meaning more effectively.

### Core Principles

1. **Each unique word gets a unique numeric value (token)**
2. **The specific value assigned doesn't matter** - what matters is consistency
3. **The same word always receives the same value**
4. **New words get new values when encountered**

## Simple Word Encoding Example

### Example 1: "I love my dog"

| Word | Token Value |
| ---- | ----------- |
| I    | 1           |
| love | 2           |
| my   | 3           |
| dog  | 4           |

**Encoded sentence**: [1, 2, 3, 4]

### Example 2: "I love my cat"

| Word | Token Value |
| ---- | ----------- |
| I    | 1           |
| love | 2           |
| my   | 3           |
| cat  | 5 (new)     |

**Encoded sentence**: [1, 2, 3, 5]

### Observing Similarity

Comparing the two sentences:

- "I love my dog" → [1, 2, 3, 4]
- "I love my cat" → [1, 2, 3, 5]

The encoding reveals structural similarity:

- First three words are identical (same tokens)
- Only the last word differs (4 vs 5)
- The neural network can now begin to recognize patterns and similarities between sentences

## Advantages of Word-Based Encoding

1. **Semantic preservation**: Words maintain their identity
2. **Reusability**: Previously seen words reuse their assigned tokens
3. **Pattern recognition**: Similar sentences produce similar token sequences
4. **Neural network compatibility**: Provides numerical input that networks can process

## Implementation

TensorFlow and Keras provide APIs that simplify the implementation of word-based encoding, making this process straightforward for developers.

# 3. Using APIs

## Overview

This section introduces how to use TensorFlow and Keras **APIs** to handle word-based encodings efficiently. Instead of manually assigning numeric values to words, TensorFlow provides built-in tools to automate tokenization, vocabulary creation, and text-to-vector conversion.

The key API used here is the **TextVectorization** layer — a high-level component designed to preprocess text for neural networks by converting sentences into consistent numeric representations.

---

## Text Vectorization Layer

### Purpose

The `TextVectorization` layer automates several key preprocessing steps:

- Building a vocabulary from text data
- Converting sentences into sequences of integer tokens
- Handling casing and punctuation
- Managing unknown or missing words

This significantly reduces manual effort and ensures consistency in data processing.

---

## Step-by-Step Code Explanation

### 1. Creating Input Sentences

Two example sentences are defined:

```python
sentences = ["I love my dog", "I love my cat"]
```

Note that “I” is capitalized at the start, as it would be in proper grammar.

---

### 2. Initializing the Text Vectorization Layer

```python
from tensorflow.keras.layers import TextVectorization

vectorizer = TextVectorization()
```

- This creates an instance of the layer that will learn how to map words to tokens.
- TensorFlow provides multiple customization options, but here the default configuration is used.

---

### 3. Building the Vocabulary with `adapt()`

```python
vectorizer.adapt(sentences)
```

- The **`adapt()`** method analyzes the input text and **generates a vocabulary** based on all unique words found.
- This method essentially “learns” the language of the dataset.

---

### 4. Viewing the Vocabulary

```python
vocab = vectorizer.get_vocabulary()
print(vocab)
```

- The **`get_vocabulary()`** method returns a list of all words identified during adaptation.
- You can print this list to see which words were recognized and how they were indexed.

---

## Automatic Text Cleaning

The TextVectorization layer performs **automatic preprocessing** to make data more uniform:

### 1. Lowercasing

Even though “I” was capitalized, the vocabulary converts it to lowercase automatically.

- Example: `"I"` → `"i"`

This ensures consistency and avoids treating `"I"` and `"i"` as different words.

### 2. Removing Punctuation

When a new sentence like `"you love my dog!"` is added, the exclamation mark (`!`) is automatically stripped out:

- `"dog!"` → `"dog"`

This prevents punctuation from creating duplicate tokens such as `"dog"` and `"dog!"`.

After re-running `adapt()` with this new sentence, the updated vocabulary will include the new word `"you"` but not a separate token for `"dog!"`.

---

## Example Result

After adding the new sentence:

```python
sentences = ["I love my dog", "I love my cat", "you love my dog!"]
```

The resulting vocabulary might look like:

```
['', 'i', 'love', 'my', 'dog', 'cat', 'you']
```

Here:

- The words are in lowercase
- `"dog!"` is merged into `"dog"`
- `"you"` appears as a new entry

---

## Special Tokens

By default, the vocabulary includes **special tokens** that serve specific purposes in text processing:

| Token               | Description                                               |
| ------------------- | --------------------------------------------------------- |
| `""` (empty string) | Used for padding shorter sequences                        |
| `"[UNK]"` (unknown) | Used for out-of-vocabulary words not seen during training |

These are added automatically when the parameter `include_special_tokens=True` (default).

If you set `include_special_tokens=False` in `get_vocabulary()`, these tokens will not appear in the output.

---

## Example: Including Special Tokens

```python
vocab_with_specials = vectorizer.get_vocabulary(include_special_tokens=True)
print(vocab_with_specials)
```

Output:

```
['', '[UNK]', 'i', 'love', 'my', 'dog', 'cat', 'you']
```

These tokens are crucial when working with real-world text, as they help models handle unknown words and maintain consistent input shapes.

# 4. Building a Vocabulary

## Overview

In this lesson, we take the **first practical step** toward preparing text data for a neural network — by **building a vocabulary**.

A vocabulary is simply the set of **unique words** that appear in the training data (the corpus). Each word in this vocabulary is assigned a unique numeric index, allowing us to represent text as numerical sequences that can be fed into models.

TensorFlow’s **`TextVectorization`** layer automates this entire process:

- Cleans and standardizes the text (lowercasing, removing punctuation)
- Tokenizes sentences into words
- Builds the vocabulary
- Maps each word to a unique integer index

---

## Key Concepts

### Why Build a Vocabulary?

Before a neural network can process text, we need a consistent mapping from words to numbers.
For example:

| Sentence      | Tokens                      |
| ------------- | --------------------------- |
| I love my dog | [2, 3, 0, 1] (example only) |

Each unique word (like _love_, _dog_, _my_) is given a numeric ID. This mapping is stored in the **vocabulary**.

Later, this vocabulary will be used for:

- **Embedding layers** (turning words into dense numeric vectors)
- **Handling unknown words** (words not seen during training)
- **Padding sequences** to ensure uniform input length

# 5. Text to Sequence

## Overview

In the previous lesson, we built a **vocabulary** — a mapping of each unique word to an integer ID.
Now, we’ll take the next crucial step: **turning sentences into sequences of numbers** based on that vocabulary.

This process is known as **text-to-sequence conversion**, and it’s what allows us to feed textual data into a neural network.

You’ll also learn about **padding**, which ensures all sequences are of the same length — a requirement for most deep learning models.

---

## Key Concepts

### 1. From Words to Numbers

Once a vocabulary is built, we can replace each word in a sentence with its corresponding integer index.

Example:

```
Sentence: "I love my dog"
Vocabulary: { "": 0, "[UNK]": 1, "my": 2, "love": 3, "dog": 4, "i": 5 }
```

→ Sequence: `[5, 3, 2, 4]`

Each word is now represented numerically using the vocabulary created by the `TextVectorization` layer.

---

### 2. Why We Need Equal-Length Sequences

Neural networks expect **uniform input shapes** — just like all images in a CNN need to be the same size.
However, sentences naturally have different lengths:

| Sentence                | Token Count |
| ----------------------- | ----------- |
| "I love my dog"         | 4           |
| "I love my amazing dog" | 5           |
| "You love cats"         | 3           |

To feed these into the same network, we must make their lengths equal.
We do this using **padding**.

---

## Step-by-Step Example

### 1. Import TensorFlow

```python
import tensorflow as tf
```

---

### 2. Define Sentences

```python
sentences = [
    'i love my dog',
    'i love my cat',
    'you love my dog',
    'do you think my dog is amazing'
]
```

Notice that:

- The first three sentences have **4 words**.
- The last one has **6 words** — this will help us demonstrate **padding**.

---

### 3. Create and Adapt the TextVectorization Layer

```python
vectorize_layer = tf.keras.layers.TextVectorization()
vectorize_layer.adapt(sentences)
```

The layer scans the sentences, tokenizes them, and builds a vocabulary automatically.

---

### 4. View the Vocabulary

```python
vocab = vectorize_layer.get_vocabulary()
for i, word in enumerate(vocab):
    print(i, word)
```

**Example Output:**

```
0
1 [UNK]
2 my
3 dog
4 love
5 i
6 you
7 cat
8 do
9 think
10 is
11 amazing
```

---

### 5. Convert Sentences to Sequences

```python
sequences = vectorize_layer(sentences)
print(sequences)
```

**Example Output:**

```
<tf.Tensor: shape=(4, 7), dtype=int64, numpy=
array([
 [ 5,  4,  2,  3,  0,  0,  0],
 [ 5,  4,  2,  7,  0,  0,  0],
 [ 6,  4,  2,  3,  0,  0,  0],
 [ 8,  6,  9,  2,  3, 10, 11]
])>
```

---

### 6. Understanding the Output

Each row represents a **sentence** encoded as integers.
For instance:

| Sentence                         | Encoded Sequence          |
| -------------------------------- | ------------------------- |
| "i love my dog"                  | `[5, 4, 2, 3, 0, 0, 0]`   |
| "i love my cat"                  | `[5, 4, 2, 7, 0, 0, 0]`   |
| "you love my dog"                | `[6, 4, 2, 3, 0, 0, 0]`   |
| "do you think my dog is amazing" | `[8, 6, 9, 2, 3, 10, 11]` |

The zeros `0` represent **padding tokens** added to make all sequences the same length.

---

### 7. Why Padding Is Important

Padding ensures all sentences in the batch have equal length.
Without padding, neural networks can’t batch-process the data properly because each sentence would have a different shape.

By default, the `TextVectorization` layer performs **post-padding**, meaning zeros are added **after** the sentence.

| Type                       | Example              |
| -------------------------- | -------------------- |
| **Post-padding (default)** | `[5, 4, 2, 3, 0, 0]` |
| **Pre-padding**            | `[0, 0, 5, 4, 2, 3]` |

We’ll learn about **pre-padding** in the next lesson.

---

## 8. Encoding a New Sentence

Let’s see what happens when we try to encode a **new unseen sentence**.

```python

```

**Output:**

```

```

Here, the word `"hamster"` was **not in the vocabulary**, so it was replaced with `[UNK]` (index `1`).

---

## Summary

| Concept              | Description                                                            |
| -------------------- | ---------------------------------------------------------------------- |
| **Text to Sequence** | Converts words into integer tokens using the learned vocabulary        |
| **Padding**          | Ensures all sequences have the same length by adding zeros             |
| **Post-padding**     | Adds zeros to the end of shorter sequences (default)                   |
| **[UNK] Token**      | Used for words not found in the vocabulary                             |
| **Tensor Output**    | The result is a tensor of equal-length sequences ready for model input |

---

### 💡 Analogy

Think of text sequences like **rows of data in a spreadsheet**.
Each sentence must have the **same number of columns** (tokens), so shorter rows are filled with blanks (zeros).

This uniformity allows neural networks to efficiently process them in **batches** — just like feeding identically sized images into a CNN.

# 6. Padding

## Overview

In the previous lesson, we learned how TensorFlow’s **TextVectorization** layer automatically performs **post-padding** — adding zeros **after** shorter sentences to make all sequences the same length.

In this lesson, you’ll learn:

- What **pre-padding** is,
- How to **control where padding appears**,
- How to use **`pad_sequences()`** from `keras.utils`, and
- How to use **ragged tensors** to manage sequences of different lengths before padding.

---

## 1. Why Padding Matters

Neural networks require **inputs of the same length** for batch processing.

If one sentence has 4 tokens and another has 7, we need to make them uniform.
We can do this by **adding zeros (padding)** — either **before** or **after** the sentence.

| Padding Type               | Example                 |
| -------------------------- | ----------------------- |
| **Post-padding** (default) | `[5, 4, 2, 3, 0, 0, 0]` |
| **Pre-padding**            | `[0, 0, 0, 5, 4, 2, 3]` |

TensorFlow’s `TextVectorization` layer **automatically applies post-padding**, but sometimes — such as in recurrent neural networks (RNNs) — **pre-padding** can work better.

---

## 2. When to Use Pre-padding

Pre-padding is helpful for models like LSTMs or GRUs that process data sequentially from left to right.
Padding at the start allows the model to focus on the most recent (rightmost) words rather than learning from trailing zeros.

---

## 3. Manual Pre-padding with `pad_sequences()`

The function `tf.keras.utils.pad_sequences()` allows full control over padding.

### Step-by-step Example

```python
import tensorflow as tf
from tensorflow.keras.preprocessing.sequence import pad_sequences
```

### Define your sentences

```python
sentences = [
    'i love my dog',
    'i love my cat',
    'you love my dog',
    'do you think my dog is amazing'
]
```

### Create and adapt a TextVectorization layer

```python
vectorize_layer = tf.keras.layers.TextVectorization(output_mode='int')
vectorize_layer.adapt(sentences)
```

---

## 4. Get the Raw (Unpadded) Sequences

The default vectorizer adds padding automatically.
To stop that and keep original lengths, you can process the sentences differently.

### Method 1 — Using `tf.data.Dataset`

```python
dataset = tf.data.Dataset.from_tensor_slices(sentences)
sequences = dataset.map(lambda x: vectorize_layer(x))
```

This creates a **map dataset** where each sentence has its original tokenized length.

You can check them by iterating:

```python
for seq in sequences:
    print(seq.numpy())
```

Example Output:

```
[5 4 2 3]
[5 4 2 7]
[6 4 2 3]
[8 6 9 2 3 10 11]
```

---

## 5. Apply Pre-padding

Now that sequences have **different lengths**, we can use `pad_sequences()`:

```python
from tensorflow.keras.preprocessing.sequence import pad_sequences

padded = pad_sequences(
    [seq.numpy() for seq in sequences],
    padding='pre'
)
print(padded)
```

**Output:**

```
array([
 [0, 0, 0, 5, 4, 2, 3],
 [0, 0, 0, 5, 4, 2, 7],
 [0, 0, 0, 6, 4, 2, 3],
 [8, 6, 9, 2, 3, 10, 11]
])
```

✅ Each sentence is now the same length (7).
✅ Zeros are added **at the front** — this is **pre-padding**.

If you omit `padding='pre'`, pre-padding still occurs by default.

---

## 6. Alternative: Using Ragged Tensors

Instead of managing padding manually, you can configure the TextVectorization layer to output **ragged tensors**.

A **ragged tensor** is like a tensor that can hold lists of different lengths (no padding).

### Example

```python
vectorize_layer = tf.keras.layers.TextVectorization(
    output_mode='int',
    ragged=True
)
vectorize_layer.adapt(sentences)
```

```python
ragged_sequences = vectorize_layer(sentences)
print(ragged_sequences)
```

Output:

```
<tf.RaggedTensor [[5, 4, 2, 3], [5, 4, 2, 7], [6, 4, 2, 3], [8, 6, 9, 2, 3, 10, 11]]>
```

Each row maintains its own length — **no automatic padding** yet.

You can still pad them afterward using `pad_sequences()` if needed:

```python
padded = pad_sequences(ragged_sequences.to_list(), padding='pre')
print(padded)
```

Same output as before — uniform pre-padded sequences.

---

## 7. Summary

| Concept           | Description                                                                    |
| ----------------- | ------------------------------------------------------------------------------ |
| **Padding**       | Adding zeros so all sequences have the same length                             |
| **Post-padding**  | Adds zeros at the end (default in TextVectorization)                           |
| **Pre-padding**   | Adds zeros at the start (default in `pad_sequences()`)                         |
| **Ragged Tensor** | Tensor that allows sequences of different lengths before padding               |
| **Use case**      | Pre-padding helps for RNN/LSTM inputs; post-padding for CNN/Transformer models |

---

### 💡 Key Takeaway

Padding ensures consistent input shapes for your model.
You can:

- Use `pad_sequences()` for **manual pre-padding**, or
- Output **ragged tensors** for more flexibility.

# 7. Out-of-Vocabulary (OOV) Words

## Overview

When working with real-world text data, it’s common to encounter **words that were not present** in the training dataset. These are known as **Out-of-Vocabulary (OOV)** words. Handling them correctly is crucial because neural networks depend on consistent numerical mappings between words and tokens — if the mapping changes, the model’s understanding becomes meaningless.

The **TextVectorization** layer in Keras automatically handles OOV words using a special token called `[UNK]` (short for _unknown_).

---

## How the TextVectorization Layer Handles Unknown Words

The `TextVectorization` layer learns a **vocabulary** when you call `adapt()` on your training sentences.  
Any new word that wasn’t seen during this phase is automatically replaced by the **unknown token** (`[UNK]`).

This ensures that:

- The model never receives undefined values.
- New words are consistently represented as a single, known token.
- The vocabulary remains fixed during inference (prediction).

---

## Example: Training and Testing with New Words

### 1. Define Training Sentences

```python
train_sentences = [
    "I love my dog",
    "I love my cat",
    "You love my dog!",
    "Do you love your dog"
]
```

### 2. Create and Train the TextVectorization Layer

```python
from tensorflow.keras.layers import TextVectorization

vectorize_layer = TextVectorization()
vectorize_layer.adapt(train_sentences)
```

After `adapt()`, the layer builds its vocabulary from these four sentences.

---

### 3. Define Test Sentences with Unseen Words

```python
test_sentences = [
    "I really love my dog",     # ‘really’ is new
    "She loves my manatee"      # ‘loves’ and ‘manatee’ are new
]
```

---

### 4. Vectorize the Test Sentences

```python
vectorized = vectorize_layer(test_sentences)
print(vectorized)
```

Output (example):

```
[[6 1 3 2 4]
 [1 1 2 1]]
```

Here’s what happens:  
| Word | Known? | Encoded As |
|-------|--------|------------|
| I | ✅ | 6 |
| really | ❌ | 1 (`[UNK]`) |
| love | ✅ | 3 |
| my | ✅ | 2 |
| dog | ✅ | 4 |
| She | ❌ | 1 (`[UNK]`) |
| loves | ❌ | 1 (`[UNK]`) |
| manatee | ❌ | 1 (`[UNK]`) |

---

### 5. Understanding the `[UNK]` Token

- The `[UNK]` token always corresponds to **index `1`** in the vocabulary.
- Index `0` is reserved for padding (empty string `""`).
- All OOV words map to `1`, ensuring consistency.

So, when the layer encounters `"really"`, `"loves"`, or `"manatee"`, it replaces them with the `[UNK]` token ID.

---

## Why Consistent Vocabularies Matter

If you train a model using one vocabulary and later try to use a **different one** during inference, the same word might map to a completely different index — leading to **nonsense predictions**.

Therefore:  
✅ Always **reuse the same TextVectorization layer** (or its saved vocabulary) during inference.  
❌ Never rebuild or re-adapt it on test data.

---

## Summary

| Concept                     | Description                                             |
| --------------------------- | ------------------------------------------------------- |
| **OOV (Out-of-Vocabulary)** | Words not seen during `adapt()` training                |
| **Token Used**              | `[UNK]` (unknown token), ID = `1`                       |
| **Padding Token**           | Empty string `""`, ID = `0`                             |
| **Handled By**              | `TextVectorization` layer automatically                 |
| **Purpose**                 | Keeps inputs consistent and model interpretable         |
| **Best Practice**           | Use the same vocabulary for both training and inference |

---

## Key Takeaway

The **TextVectorization layer** ensures robustness by automatically replacing unknown words with a special token.  
This prevents runtime errors, preserves input consistency, and allows models to handle unseen text gracefully — an essential feature for real-world NLP applications.

# 8. Notebook for Lesson 2 – Text Preprocessing in Action

This lesson demonstrates how to **convert text into integer sequences**, **pad them to uniform length**, and **handle out-of-vocabulary (OOV) words** using TensorFlow’s `TextVectorization` layer.

---

## 1. Setting Up the Sample Data

```python
import tensorflow as tf

# Sample sentences
sentences = [
    'I love my dog',
    'I love my cat',
    'You love my dog!',
    'Do you think my dog is amazing?'
]
```

---

## 2. Initialize the TextVectorization Layer

```python
# Initialize the layer
vectorize_layer = tf.keras.layers.TextVectorization()

# Build the vocabulary from the sentences
vectorize_layer.adapt(sentences)

# Retrieve the vocabulary
vocabulary = vectorize_layer.get_vocabulary()

# Print token indices
for index, word in enumerate(vocabulary):
    print(index, word)
```

- Tokens with **lower indices** are more frequent words.
- Index `0` is reserved for **padding**.
- Index `1` is reserved for **unknown (OOV) tokens**.

---

## 3. Convert a Single Sentence to a Sequence

```python
sample_input = 'I love my dog'

# Convert to integer sequence
sequence = vectorize_layer(sample_input)

print(sequence)  # Example output: [6 3 2 4]
```

- Each word is replaced by its corresponding **integer index** from the vocabulary.

---

## 4. Convert Multiple Sentences Using `map()`

```python
# Convert list to tf.data.Dataset
sentences_dataset = tf.data.Dataset.from_tensor_slices(sentences)

# Apply vectorization to each element
sequences = sentences_dataset.map(vectorize_layer)

# Print results
for sentence, sequence in zip(sentences, sequences):
    print(f'{sentence} ---> {sequence}')
```

- Sequences may have **different lengths**, which requires padding before feeding to a model.

---

## 5. Padding Sequences

### Post-padding (default with TextVectorization)

```python
# Apply vectorization directly to the list (post-padding)
sequences_post = vectorize_layer(sentences)

print('INPUT:')
print(sentences)
print('\nOUTPUT:')
print(sequences_post)
```

- All sequences are padded with `0`s at the **end** to match the length of the longest sequence.

### Pre-padding Using `pad_sequences()`

```python
# Pre-pad sequences
sequences_pre = tf.keras.utils.pad_sequences(sequences, padding='pre')

print('INPUT:')
[print(seq.numpy()) for seq in sequences]
print('\nOUTPUT:')
print(sequences_pre)
```

- Zeros are added at the **beginning** of shorter sequences.

---

## 6. Truncating Long Sequences

```python
# Pre-pad and truncate to max length 5
sequences_post_trunc = tf.keras.utils.pad_sequences(sequences, maxlen=5, padding='pre')

print('INPUT:')
[print(seq.numpy()) for seq in sequences]
print('\nOUTPUT:')
print(sequences_post_trunc)
```

- Use `truncating='post'` to remove tokens from the **end** instead of the beginning.

---

## 7. Using Ragged Tensors

```python
# TextVectorization with ragged output
vectorize_layer = tf.keras.layers.TextVectorization(ragged=True)
vectorize_layer.adapt(sentences)

ragged_sequences = vectorize_layer(sentences)
print(ragged_sequences)
```

- Sequences retain **original lengths**.
- Can be passed to `pad_sequences()` to pre-pad or post-pad as needed.

---

## 8. Handling Out-of-Vocabulary (OOV) Words

```python
sentences_with_oov = [
    'i really love my dog',
    'my dog loves my manatee'
]

sequences_with_oov = vectorize_layer(sentences_with_oov)

# Print results
for sentence, sequence in zip(sentences_with_oov, sequences_with_oov):
    print(f'{sentence} ---> {sequence}')
```

- Words not in the vocabulary (like `really`, `loves`, `manatee`) are replaced by **token index 1**.

---

## ✅ Key Takeaways

1. **TextVectorization** converts strings to integer sequences.
2. **Padding** ensures all sequences have uniform length for neural network input.
3. **Truncation** allows limiting sequence length.
4. **Ragged tensors** maintain variable sequence lengths before padding.
5. **OOV tokens** handle unseen words consistently.

This prepares text data for feeding into neural networks for tasks like **text classification, sentiment analysis, or sequence modeling**.

## 5. Vectorizing Text

We convert text into **integer sequences** using a `TextVectorization` layer.

### 5.1 Post-Padded Sequences

```python
# Initialize vectorization layer
vectorize_layer = tf.keras.layers.TextVectorization()

# Build the vocabulary from sentences
vectorize_layer.adapt(sentences)

# Convert text to integer sequences
post_padded_sequences = vectorize_layer(sentences)
```

**Explanation:**

- `TextVectorization()` automatically:

  1. Splits each headline into tokens (words)
  2. Assigns a unique integer index to each word in the vocabulary
  3. Converts each headline into a sequence of integers

- Post-padding adds zeros **at the end** so that all sequences have the same length.

**Example:**

```python
sample_index = 2
print(sentences[sample_index])
# "mom starting to fear son's web series closest thing she will have to grandchild"

print(post_padded_sequences[sample_index])
# [140, 825, 2, 813, 1100, 2048, 571, 5057, 199, 139, 39, 46, 2, 13050, 0, 0, 0,...]
```

- The last zeros are **post-padding** to make the length uniform.
- Shape of sequences: `(26709, 39)` → 26,709 headlines, each padded to 39 tokens.

---

### 5.2 Pre-Padded Sequences

If you want **zeros at the beginning**, we need **ragged sequences**:

```python
# Initialize with ragged=True
vectorize_layer = tf.keras.layers.TextVectorization(ragged=True)
vectorize_layer.adapt(sentences)

# Convert text to ragged sequences
ragged_sequences = vectorize_layer(sentences)

# Pre-pad sequences
pre_padded_sequences = pad_sequences(ragged_sequences.numpy())
```

**Explanation:**

- `ragged=True` allows sequences of variable length before padding.
- `pad_sequences()` adds zeros **at the beginning** (pre-padding).

**Example:**

```python
pre_padded_sequences[2]
# [0, 0, 0, 0, ..., 140, 825, 2, 813, 1100, 2048, 571, 5057, 199, 139, 39, 46, 2, 13050]
```

- Shape matches post-padded: `(26709, 39)`, only difference is **position of zeros**.
